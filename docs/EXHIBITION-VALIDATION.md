## 추가 수정

1. HTTP LAN 접속에서 `crypto.randomUUID`가 없으면 채팅 전송 준비 단계가 예외로 끝나는 경로를 수정했다. `getRandomValues`로 UUID를 생성하도록 대체하며, 해당 환경의 ID 1,000개 형식·고유성 및 네이티브 UUID 사용 경로를 테스트한다. 메시지 중복 방지 ID이며 인증 토큰이 아니다.
2. 다른 방으로 이동한 뒤 이전 방 조회가 실패했을 때 새 방 메시지와 로딩 상태를 덮어쓰던 비동기 콜백에 현재 방 검사를 추가했다. 이전 요청의 읽음 배지 변경도 막았다. 이 화면 전환은 코드 검토와 빌드로 확인했으며 실제 브라우저 지연 주입 테스트는 아직 실행하지 않았다.

## 테스트 DB 정리

새 테스트는 `jdbc:h2:mem:exhibition-races` 전용 메모리 DB를 사용한다. 다른 테스트 DB와 분리해 컨텍스트 종료 시 서로의 테이블을 삭제하지 않게 했다. `create-drop`과 테스트 컨텍스트 종료로 테이블 및 연결을 정리한다. 최종 테스트 JVM 종료를 확인했으며 남겨 둔 DB 파일은 없다. 운영 DB에 접속하거나 데이터를 변경하지 않았다.

## 사용자 확인 및 남은 검증 범위

- 사용자는 휴대폰 두 대의 전체 동선, 실제 이메일·푸시 수신 및 운영 환경 정상 동작을 직접 확인했다고 보고했다. 최근 채팅 수정 2개까지 해당 환경에 반영됐는지는 별도 확인이 필요하다.
- 제공된 Gmail·네이버 수신 원문에서 SPF·DKIM·DMARC 모두 PASS를 확인했다. Gmail에서는 스팸 분류가 발생했고, 사용자는 네이버에서는 일반 메일함으로 들어온 것으로 기억한다고 답했다. 네이버 원문은 9월 3일, Gmail 원문은 11월 3일 자료이므로 동일 시점 비교는 아니다. 가입 화면에는 기존 스팸함 확인 안내가 있으며 시연에서도 안내하기로 했다.
- 운영 MySQL의 동시 실행과 마이그레이션 적용 여부는 별도 검증하지 않았다. H2 통과만으로 운영 MySQL의 잠금 동작까지 검증한 것은 아니다.
- 빌드에는 기존 약 516 kB 앱 청크 크기 경고가 남아 있다.
