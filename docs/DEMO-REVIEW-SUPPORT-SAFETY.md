# 반띵: AI 후기, 문의하기, 시연 악용 방지

## 1. 완료 기준 유지 + 대화에 맞는 후기
- 일반 거래 완료 정책은 바꾸지 않았습니다. 사용자가 완료 버튼을 먼저 누르면 자동 상대가 나머지 완료 확인을 진행합니다.
- 양측 완료 후 실제 저장된 채팅 최근 최대 24개 메시지와 게시글 종류·품목을 AI에 전달해 짧은 후기와 **4·5점 가운데 하나**를 작성합니다.
- AI 자동 평가는 **정상적으로 대화하고 완료되면 기본 5점**이며, 반복되고 명백하게 심각한 불편이 있었을 때만 4점입니다. 짧은 대화나 답장 지연만으로 감점하지 않습니다.
- API 장애 시엔 대화의 감사 표현 여부 등에 따라 기본 후기를 사용합니다. 대화에 없는 만남·실물 수령·배송·결제는 허위로 쓰지 않도록 지침을 설정했습니다.
- AI 생성은 DB 트랜잭션 밖에서 실행되며, 후기는 거래별 작성자당 중복 저장하지 않습니다.
- 기존 `demo_sessions`와 새 `demo_inbound_jobs` 양쪽에 모두 적용했습니다.

## 2. 공지사항
- 설정의 공지사항에 표시되던 과거 패치 노트 목록을 제거했습니다.
- 목록 대신 '등록된 공지사항이 없습니다.'라는 빈 상태만 표시합니다.

## 3. 문의하기: 실제 이메일 전송
- 설정 > 문의하기에 유형, 제목(2~100자), 내용(10~3000자) 입력 화면을 추가했습니다.
- 로그인 회원만 `POST /api/support/inquiries`로 전송할 수 있습니다.
- **메일 전송 성공 이후에만** 완료 안내를 표시합니다. SMTP 설정이 없거나 전송에 실패하면 사용자에게 오류를 표시하며 성공으로 처리하지 않습니다.
- 운영자 수신 주소는 `SUPPORT_INBOX_EMAIL` 환경변수로 지정합니다. 생략하면 `MAIL_FROM`(이메일 인증 발신 계정)으로 보냅니다.
- 운영 서버의 `.env.docker` 예시:
  ```bash
  MAIL_HOST=smtp.gmail.com
  MAIL_PORT=587
  MAIL_USERNAME=your-sender@example.com
  MAIL_PASSWORD=your-smtp-app-password
  MAIL_FROM=your-sender@example.com
  SUPPORT_INBOX_EMAIL=your-inbox@example.com
  ```
  위 주소는 **예시**이므로 실제 운영자가 사용하는 메일 계정을 직접 지정해야 합니다. 비밀번호를 GitHub에 올리지 마세요.
- 보내는 메일은 `MAIL_FROM`에서 발송되고 답장 주소는 문의 회원의 가입 이메일입니다.
- 계정별 시간당 3건·하루 8건으로 문의 스팸을 제한합니다. 이 한도는 인증 관련 이메일과 별도입니다.

## 4. 악용 보호 (시연 기능만)
- AI의 주관적 의견이나 사진 인식 결과로 계정을 제한하지 않습니다. 엉뚱한 질문, 오타, 일회성 장난, 거친 단어의 인용만으로는 차단하지 않습니다.
- **동일 계정이 10분 안에** 시연모드 상태로 게시글을 30건 초과 작성하거나, 시연 게시글 거래 요청을 50건 초과 보내거나, 시연 채팅을 90건 초과 보낼 때만 일시 중지합니다.
- 최초 초과 시 **1분**, 24시간 안에 반복 초과하면 **10분**간 해당 계정의 AI 체험이 제한되고 자동 해제됩니다.
- 일반 거래 계정 정지, 계정 삭제, 일반 채팅 차단과는 무관합니다. 시연 참여만 계정별로 일시 중지합니다.
- 시연 계정이 서버 내부에서 보내는 **자동 메시지**는 별도 서버 내부 메서드를 사용하므로 카운트에서 제외됩니다. 외부 사용자가 AI 발신으로 가장해 우회할 수 없습니다.
- 시연모드가 꺼지면 이 제한 로직은 일반 거래에 개입하지 않습니다.
- 문제 시 '새파란' 또는 '메로' 중 시연 관리자 권한이 있는 계정은
  `POST /api/demo-mode/restore-account/{targetUserId}`로 해당 사용자 제한을 해제할 수 있습니다. 모든 사용자 데이터를 삭제하는 명령이 아닙니다.

## 5. 식재료 관련성 및 명백한 괴롭힘

- **이미지·게시글 내용 검사:** 시연모드에서 새 나눔·판매·구매 게시글이 등록되면 약 10초 뒤 자동 요청을 보내기 전에 제목·재료·설명·사진을 함께 AI에 전달하여 관대하게 확인합니다. AI 호출은 트랜잭션 밖에서 진행합니다.
- 음식·식재료·음료·간식·보관·조리·주방 관련 물품 등 폭넓은 관련성을 인정합니다. 사진이 없거나 불분명한 경우, AI가 오류를 낸 경우, 식재료 여부가 애매한 경우에는 모두 허용합니다.
- AI가 '명백히 무관함'이라고 해도, 제목·상세 설명에 코인 투자/토토 광고/전자제품 판매 등 **매우 명시적인 비식재료 광고 단서가 함께 있는 경우**에만 해당 게시글의 자동 거래 요청을 생략합니다. **게시글은 삭제하지 않고, 계정도 제한하지 않습니다.**
- 게시글 작성자 본인이 기존에 올린 AI 시연 게시글에 요청하는 방식에서는 별도 사진 판정 없이 기존 요청·차단·도배 방지 규칙이 적용됩니다.
- **명백한 욕설 및 성적 괴롭힘:** AI와의 거래 채팅에서 직접적인 인신모욕·성적 사진 요구·성관계 요구 등 매우 구체적인 표현만 검사합니다. 교육/설명/인용 등 의도가 뚜렷하면 계산하지 않습니다.
- 위반한 메시지는 **채팅방에 저장되지 않고 AI에게 전달되지 않습니다.** 응답도 생성되지 않습니다. 정상적인 대화에서 발생한 오판을 줄이기 위해 한두 번의 모호한 표현은 제재하지 않습니다.
- **24시간 내 명백한 위반 메시지가 세 번 누적**되면 해당 계정의 AI 시연 참여를 **기한 없이 제한**합니다. 일반 거래·로그인·게시글 작성 자체는 차단하지 않습니다.
- 이 영구적 시연 제한도 관리자 승인으로 풀 수 있습니다. 기존 `POST /api/demo-mode/restore-account/{targetUserId}` 엔드포인트로 해당 사용자 제한 기록을 초기화합니다. 발표 전 테스트 계정 제한 해제를 점검하십시오.
- 자동 AI 채팅 메시지는 위반 횟수나 도배 횟수에 포함되지 않습니다.

## 6. 배포 체크
1. 운영 MySQL을 백업합니다. 새로운 `demo_participation_controls` 테이블이 생성됩니다.
2. Gradle 백엔드 테스트(`./gradlew test`), 프론트엔드 빌드(`npm run build`)를 실행합니다.
3. 운영 SMTP 설정값을 비밀 환경파일에서 확인합니다.
4. 문의하기 기능을 운영자 테스트 계정으로 한 번 전송해 메일 수신·답장 주소가 맞는지 확인합니다.
5. 두 방향 시연에서 완료 버튼 후 자동 4~5점 후기 저장, 신선도 적용을 확인합니다.
6. 악용 제한은 일반 시연 중 발동하지 않아야 하고, 계정만 제한되며 1분 후 풀리는지 확인합니다.

**이 문서는 GitHub 코드 변경 설명입니다. 작성 시점에 운영 배포와 실제 SMTP 발송·빌드 성공을 확인한 결과는 아닙니다.**

- AI 관련성 검사에 따른 자동 거래 요청 생성·생략(정상 식재료, 사진 불분명, 명백한 비식재료 광고)을 테스트합니다.
- 명백한 욕설/성적 요구 3회 반복의 계정별 기한 없는 AI 체험 제한, 관리자 수동 해제, 일반 거래 비영향을 확인합니다.
- 테스트 계정 및 운영 중 시연 계정의 채팅·후기 데이터를 초기화하기 전 DB 백업을 확보합니다.
