# 기능·상태·운영 공백 수정 내역

기준 커밋: `a839865`. 수정일: 2026-11-04.

앞서 점검한 36개 문제·기능 공백과 7개 추가 검증 항목의 처리표다. 운영 서버 배포나 운영 DB 변경을 수행했다는 의미는 아니다.

## 변경된 사용 규칙

- 거래는 양쪽이 완료를 확인해야 확정된다. 한쪽만 확인한 동안에도 취소할 수 있다. 이미 완료한 거래의 분쟁은 거래내역에서 접수하고 운영자가 조정할 수 있다.
- 시장·공동구매·열린 냉장고 일반 나눔은 대기 요청 철회와 수락 후 취소를 지원한다. 송금 금액은 자동 환불되지 않는다.
- 공동구매는 개별 수락·거절과 전체 취소를 제공한다. 모집 중에는 완료할 수 없다.
- 맞교환은 상호 취소를 유지하며, 취소 요청 후 48시간이 지나거나 차단 관계가 되면 상대 응답 없이 종료할 수 있다.
- 거래 요청이 있는 게시글의 조건은 수정할 수 없다. 진행 거래가 있으면 글 삭제를 거절하고, 대기 요청만 있으면 삭제와 함께 요청을 종료한다. 거래 기록은 개인 내역에서 별도로 숨긴다.
- 차단은 양방향이다. 단체방에서는 차단 상대 메시지·미리보기·알림을 제외하고 나머지 참여자의 대화를 유지한다.
- 공개 게시글은 동네와 소수점 둘째 자리의 대략 좌표를 제공한다. 공개 거리 검색도 같은 좌표 정밀도를 사용한다. 상세 약속은 채팅으로 정한다.
- 게시글 사진은 현재 모델에 맞춰 1장으로 명시한다. AI 분석은 실제로 분석한 원본 사진과 일치하는 업로드에만 연결할 수 있다.
- 회원가입은 이메일로 인증번호를 발송·검증하고 전화번호는 DB 연락처로 저장하는 기존 구조를 유지한다. 전화번호 중복 제한과 이름·전화번호로 가입 이메일 찾기를 복원했다. 별도의 미사용 전화 인증 API는 회원가입 흐름과 관계가 없다.

## 기존 DB와 운영 설정

`application.yml`의 `ddl-auto:update`는 새 필드를 추가한다. 전화번호 unique 인덱스는 원래대로 유지하며, 이전 수정본으로 해제된 DB에는 고유 제약 복원 검사를 제공한다. 운영 DB에 적용할 때는 신규 스키마 반영 후 `MIGRATION-2026-11-04.sql`을 사용한다. 이 채팅에서는 운영 DB에 실행하지 않았다.

마이그레이션에는 연락처 고유 제약 유지·복원 검사, 레거시 직접 채팅 참여자·읽음 정보 보존, 리뷰 중복 확인과 고유 인덱스 확인, 이전 세션의 일회성 종료가 포함된다. 중복 리뷰는 자동 삭제하지 않는다. 과거 약관 동의·완료 확인·사진 지문을 임의로 채우지 않는다.

관리자 조치는 로그인 토큰과 32자 이상의 별도 `app.admin.token`이 필요하다. 기본 개발용 토큰으로 조치할 수 없다. `PATCH /api/admin/reports/{id}`에 `status`, `action`, `resolution`을 전달한다. 지원 조치는 `NONE`, `HIDE_POST`, `SUSPEND_USER`, `RESTORE_USER`, `CANCEL_TRADE`이며 실제 조치에는 사유가 필요하다.

기존 클라이언트는 새 필드와 완료 확인 규칙을 함께 사용하도록 프런트와 백엔드를 같이 배포한다. 운영 DB 적용과 서비스 배포는 코드의 Git 반영과 별도로 진행한다.
