# 공동구매 시연: AI 두 명 — 2026-11-11

## 동작

- 시연 원본 글의 정원이 2명이면 사용자와 주최자 AI만 연결된다.
- 정원이 3명 이상인 시연 원본은 개인 체험용 복사본의 정원을 3명으로 제한하고, 주최자 AI A와 별도 참가자 AI B를 연결한다. A와 B는 서로 다른 등록된 시연 계정이며 사용자와도 다르다.
- 정방향은 사용자가 먼저 말한다. A의 답장이 저장된 뒤 최소 2초가 지나야 B가 답한다. B는 A의 답장을 참고하고 자기 역할로 말한다. 새 사용자 발화 없이 AI끼리 계속 대화하지 않는다.
- 사용자 작성 공동구매는 기존 A 요청 약 10초 후 B도 요청한다. 정원 및 실제/대기 참여 요청을 확인하고 최대 두 AI까지만 추가한다. 정원 2명, 조기 모집 마감, 실제 참여자로 빈자리가 없는 경우 B를 추가하지 않는다.
- 수락·모집 마감/정원 충족으로 실제 단체방이 열린 뒤 A가 약 10초 후 인사하고 B가 이어서 인사한다. 비동기 작업/모델 응답 때문에 정확한 초 단위는 보장하지 않는다.
- B는 해당 사용자와 A의 대화만 참고한다. 다른 일반 참가자의 발언을 해당 사용자의 후기 문맥으로 넣지 않는다.
- 거래 완료는 사용자 확인을 기준으로 한다. 사용자 작성 글은 각 요청의 완료 확인 후 각 AI가 해당 거래 후기 작성. 정방향은 주최자가 사용자에게 후기 한 건 작성하며, B의 주최자와의 거래도 종료하되 AI끼리 불필요한 후기를 만들거나 사용자 평점을 중복 가산하지 않는다.
- 기존 관리자 한정 초기화는 두 AI의 거래·후기·신선도 변화와 대기 작업을 함께 정리한다. 실제 참가자의 기록과 사용자 원본 게시글을 보존한다.
- 이미 생성된 1:1 체험 채팅방에 새 AI를 소급 삽입하지 않는다. 새로 시작한 체험에 적용된다.

## 저장 및 배포

새 `demo_group_companions` 테이블은 기존 Hibernate `ddl-auto:update` 방식으로 생성한다. 게시글 ID를 기본키로 두어 두 번째 참여 작업이 중복되지 않으며, 주 거래 ID·두 번째 요청 ID·응답 커서·초기화 상태를 영속화한다. 기존 데이터 변환은 없다. 운영 DB/이전 이미지 백업 후 테스트한 JAR로 배포한다.

## 검증

전체 백엔드 테스트 및 bootJar 성공. 추가 통합 테스트는 실제 서비스/테스트 DB에서 다음을 확인한다.

- 서로 다른 세 참가자, A→B 지연 순서, 중복 응답 방지, AI끼리 무한 대화 없음.
- B 요청의 10초 지연, 두 요청 수락 후 단체방, 순차 인사/답장.
- 완료·후기·신선도 반영 및 양방향 초기화.
- 2명 정원·조기 모집마감 시 B 요청 없음.
- 시연모드 OFF·차단·초기화 후 지연 답변 차단.

AI 출력은 통합 테스트에서 대체 응답으로 검증한다. 실제 여러 휴대폰에서의 화면/푸시 수신까지 확인했다는 뜻은 아니다.
