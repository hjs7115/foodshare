# 시연모드 역방향 자동 거래 (나눔·판매·구매)

## 구현 내용

- 시연모드가 켜져 있을 때 작성된 신규 `SHARE`, `SALE`, `BUY` 게시글에만 자동 요청을 예약
- 새 `demo_inbound_jobs` 테이블에 작업 상태 저장 (글당 1회, 최초 10초 지연)
- 미리 등록된 `demo_posts` 작성자 가운데 게시글 작성자 본인이 아닌 이용 가능 계정을 자동 거래 상대 후보로 선택
- 일반 거래 API를 이용해 `PENDING` 거래 요청 생성: 작성자는 평소와 동일한 화면에서 수락/거절
- 수락 후 약 10초 뒤 자동 거래 상대가 거래 종류별로 먼저 채팅
- 이후 게시글 작성자가 메시지를 보내면 자동 응답, 이전 대화를 맥락으로 반영
- 작성자가 완료를 확인하면 자동 거래 상대가 완료 확인, 자동 5점 후기 작성
- 시연 상대라는 표시를 채팅 상단에 유지하며 일반 거래에는 영향 없음
- 기존 `채팅방이 개설되었습니다.` 시스템 메시지는 대화 UI에서 제외하고 토스트는 약 3초 후 자동 종료
- 거래 내역 화면이 열려 있을 때도 새 요청이 도착하도록 5초 간격으로 가볍게 갱신

## 주의사항

1. **운영 DB를 백업**한 뒤 스테이징/테스트 DB에서 빌드와 자동 거래 전체 흐름을 먼저 검증
2. 필요한 시연 계정은 기존 `demo_posts` 작성자 계정으로 식별; 시연 글이 없거나 상대 이용 불가면 자동 거래 요청 없음
3. 일반 사용자처럼 보이더라도 채팅에는 '거래 연습 · 자동 응답 상대'라는 고지를 유지
4. 자동 거래 완료는 **작성자가 먼저 거래 완료를 확인한 경우에만** 진행
5. 신선도 점수·후기·게시글 상태는 실제 DB에 저장되므로 운영 DB에서 테스트 전 백업 필수
6. 신규 작업은 시연모드 ON에서 생성한 **신규 게시글**만 대상으로 하며, 이전 게시글에 소급 적용되지 않음
7. 사용자가 작성한 게시글을 자동으로 삭제하지 않음
8. 기존 '내 시뮬레이션 초기화'는 종전 `demo_sessions` 방식 위주이므로 새 역방향 작업을 전체 삭제/초기화해 준다고 가정하지 말 것

## 테스트

`DemoSimulationTests`에 다음 시나리오 추가:
- 시연 글 작성자가 아닌 사용자가 SALE 글을 작성한 후 자동 요청, 수락, 10초 후 첫 메시지, 대화, 양측 완료 및 AI 후기 확인
- SHARE/BUY 요청의 유형별 인사말
- 시연모드 OFF에서는 예약 작업 미생성

테스트 코드는 추가했지만 이 GitHub 작업 환경에서 실제 Gradle 테스트는 실행하지 못했습니다.
서버 적용 전에 `./gradlew test`와 프론트엔드 빌드의 성공 결과를 확인해야 합니다.

## 계정별 체험 가능 범위 및 설정 화면 권한

- 시연모드가 켜져 있으면 **기존 계정, 신규 계정, 시연 게시글 작성자 계정 모두** 새로 작성한 나눔/판매/구매 게시글에 대해 자동 거래 요청을 받을 수 있습니다.
- 자동 거래 요청을 보내는 상대 역할은 기존에 `demo_posts`로 등록된 시연 계정 중 본인이 아닌 계정만 맡습니다. 실제 일반 사용자 계정으로 자동 요청을 보내지 않습니다.
- 예약 생성은 **시연모드 ON 상태에서 새로 작성한 게시글**에만 적용합니다. 모드 전환 이전 게시글에는 소급해서 예약 작업을 만들지 않습니다.
- `GET /api/demo-mode`의 `enabled`는 모든 계정에 실제 전역 설정을 전달합니다. `canManage`는 기존 관리자 버튼 권한이고, `canReset`은 초기화 버튼 권한입니다.
- 파란색 정보 박스는 모든 계정에 표시하되, **시뮬레이션 초기화** 버튼은 `demo_managers` 권한을 가지고 닉네임이 정확히 **새파란** 또는 **메로**인 계정에만 표시합니다.
- `POST /api/demo-mode/reset-mine`도 서버에서 같은 권한을 확인하며 권한이 없는 호출에는 403을 반환합니다.
- 해당 초기화 API의 기존 의미는 **호출한 계정 자신의 기존 시뮬레이션 내역 초기화**입니다. 모든 계정의 시뮬레이션을 일괄 삭제하는 관리자 도구는 아닙니다.
- 이미 생성된 역방향 시뮬레이션(`demo_inbound_jobs`) 전체를 초기화하는 기능은 포함되어 있지 않습니다.

## 추가 검증

- 전역 시연모드 ON 상태에서 일반 계정의 상태 응답도 `enabled:true`인지 확인
- 기존/신규/시연 계정이 각각 게시글 작성 시 예약 생성되는지 확인
- 새파란·메로 계정이 `demo_managers`에 등록돼 있어야 초기화 버튼을 사용할 수 있음
- 두 계정 외에는 파란색 안내가 비클릭 텍스트로 표시되는지, 초기화 API가 403을 반환하는지 확인

## 첫 메시지 및 알림 개선

- 시연모드 역방향 거래 요청이 수락된 후 약 10초가 지나면 AI가 **게시글 종류, 식재료명, 제목, 상세 설명, 수량, 가격, 거래 장소**를 참고해 새로운 첫 메시지를 작성합니다.
- 게시글에 `/uploads/<uuid>.jpg` 형식의 이미지가 있고 서버에서 안전하게 읽을 수 있다면 **사진을 함께 AI에 전달**합니다. 사진을 읽을 수 없을 때는 텍스트만으로 작성하며, 사진을 확인한 척하지 않습니다.
- 첫 메시지는 제목을 통째로 반복하지 않고 핵심 품목만 간단히 부르는 **자연스러운 1~2문장**을 목표로 합니다. AI 응답은 고정된 문장이 아니며 상황에 따라 달라집니다.
- 이어지는 대화도 상대 메시지의 의미에 맞춰 짧게 답하도록 프롬프트를 개선했습니다. AI API가 실패하면 기본 답변을 사용합니다.
- 외부 AI 호출은 DB 트랜잭션 밖에서 실행하고, 중복 전송 방지를 위해 작업 상태를 재확인합니다.
- 앱 화면 **상단 알림 팝업은 수신 경로와 무관하게 약 4초 후 자동 닫기**, 일반 토스트는 약 3초 후 자동 닫기입니다. 사용자의 선택이 필요한 확인·입력 대화상자는 자동으로 닫지 않습니다.

**배포 전 참고:** 이미 운영 중인 서버에는 GitHub 코드 반영만으로 적용되지 않습니다. 백엔드 테스트·프론트 빌드·시연 거래 회귀 테스트 후 배포해야 합니다.
